## 2024-05-18 - [Optimizing Typed Array loops in JS]
**Learning:** In hot JavaScript loops processing real-time audio buffers, `DataView.setInt16` adds overhead compared to manual bitwise packing. While directly backing a `Uint8Array` buffer with an `Int16Array` view avoids method call overhead completely and is up to 40% faster, it implicitly uses the system's native endianness. For protocols requiring strict little-endian formats (like typical PCM streams fed to `whisper.rs`), manual bitwise shifting into a `Uint8Array` provides a middle ground: it eliminates the `DataView` overhead (saving ~10-20% execution time) while safely enforcing endianness cross-platform. Additionally, caching the `.length` property and minimizing array lookups speeds up basic reductions like `rms`.
**Action:** When working with strictly-formatted audio buffers in tight loops, replace `DataView` calls with manual bitwise operations to save execution time while avoiding native-endianness bugs.

## 2024-06-15 - [Direct Float32 Buffer Passing Pitfalls]
**Learning:** In Tauri v2, while direct binary IPC is possible, passing a `Uint8Array` as a value inside an arguments object (e.g., `{ pcm }`) causes it to be serialized via standard `JSON.stringify()`. **Action:** When optimizing IPC boundaries, ensure the serialization method natively supports the data structure without corrupting the payload type. If trying to skip `Array.from()`, the backend must explicitly use `tauri::ipc::Request` instead of parsed arguments.
## 2024-06-16 - [Direct Binary IPC in Tauri v2]

**Action:** When migrating endpoints to raw binary IPC, verify the exact JS typed array class before invoking, and use `tauri::ipc::Request` on the Rust side to safely borrow the `&Vec<u8>` without cloning.

## 2024-08-01 - [Terminating Idle RAF Loops Completely]

## 2024-08-10 - [Removing Redundant Square Roots in Hot Loops]
**Learning:** In audio processing, `rms` is often computed as the square root of the mean of squared samples. ## 2026-07-09 - [Optimizing Hot Loops with Loop Unrolling and Multiple Accumulators]
**Learning:** In tight numerical hot loops (like computing the sum of squares of a large typed array on every audio frame), simple loop unrolling helps but still suffers from loop-carried dependency chains if only a single accumulator (e.g., `sum`) is used, as each addition must wait for the previous one to complete. **Action:** When optimizing iterative accumulation loops (like sum, dot product, or sum-of-squares) over large arrays, use multiple independent accumulator variables alongside loop unrolling to maximize ILP. Combine them after the loop.
